How Deployment Works

The site is hand-coded static HTML hosted on GitHub Pages, deployed from the main branch. The CNAME file at the repo root makes Pages serve as sanji.band. HTTPS certs are auto-provisioned by Let's Encrypt — no manual renewal.

To ship a change:

git pull
# edit files
git add .
git commit -m "what you changed"
git push

Pages rebuilds within ~1 minute. The build status shows up under the repo's Actions tab as pages-build-deployment.

Working Locally

To preview before pushing (macOS / Linux):

git clone https://github.com/notafeature/sanji.git
cd sanji
python3 -m http.server 8000
# open http://localhost:8000

Windows: replace python3 with python. Refresh in the browser after each save.

Parking Lot & Ideas

Things we've discussed but haven't built — capture-only, not commitments:

  • Move video off YouTube. Cloudflare R2 (cheap object storage, zero egress fees) or Cloudflare Stream ($5/mo, adaptive bitrate, custom player). Removes YouTube branding from the "Live" section.
  • Move DNS to Cloudflare. Pairs naturally with the video work. Squarespace keeps the registration; Cloudflare runs the records. Free tier covers everything.
  • More private admin pages. Same pattern as this one — committed to the repo, noindex,nofollow, lives at an obscure URL. Good fit for runbooks, vendor sheets, etc.
  • Press-kit polish. Spotify/Bandcamp player embed, festival logos in the Notable Performances list, alternating section tones for visual rhythm.
  • Email newsletter signup. Buttondown or Mailchimp embed, lightweight.
  • Spotify / Bandcamp embed on the main page. Either supplementing or replacing the YouTube video.

This handbook lives at handbook.html in the repo with <meta name="robots" content="noindex, nofollow"> so search engines skip it. The URL itself isn't secret — never commit passwords here. Print this page for a clean handout; the layout is print-friendly.
